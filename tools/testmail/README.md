# testmail: a disposable mailbox you can break

Testing the app used to mean pointing it at a real account. That is a bad idea twice
over: a first-run test needs `pm clear`, and anything destructive is one keystroke from
real mail. This seeds a synthetic account instead, in about a minute, as many times as
you like.

```
python seed.py --user avery@gridlink.me --wipe
```

The password comes from `--password`, from `GRIDLINK_TEST_PASSWORD`, or from a prompt.
Nothing is hardcoded: host, account, volumes and the reference date are all flags, so the
same script seeds a second account or a different server without an edit.

## What lands in the account

| | |
|---|---|
| Mail | 200 messages: 161 hand-written, the rest routine filler |
| Folders | INBOX, Archive, Sent Items, Junk Mail, Drafts |
| Contacts | 40, with monogram photos, multiple numbers, addresses, categories |
| Calendar | 30 events, including recurring, all-day, multi-day and cancelled |

The interesting parts, which is to say the parts a lazy fixture would skip:

- **Threads that span folders.** 26 conversations, threaded on `In-Reply-To` and
  `References` rather than on subject. Avery's own turns are in Sent Items, so a client
  that threads by subject alone will get them wrong and a client that threads properly
  will not.
- **A real unread mix.** Around 33 unread, weighted towards recent mail, plus `\Answered`
  on anything that was replied to and `\Draft` on the six unfinished drafts.
- **Attachments that are really that format.** PDFs, PNGs and CSVs are generated byte by
  byte from the standard library, so a PDF opens in a PDF viewer rather than being a text
  file with the wrong extension.
- **HTML newsletters with a plain-text alternative**, `List-Unsubscribe` and all. If the
  app renders only one of the two parts, these will show it.
- **iTIP.** One plain invitation, one reschedule (same UID, `SEQUENCE` bumped) and one
  cancellation, each as `multipart/alternative` with a `text/calendar; method=` part and
  an `invite.ics` attachment. The invitations are generated from the same rows as the
  calendar entries, so the mail and the calendar cannot drift apart.
- **Junk that reads like junk**, in Junk Mail, all unread.

Every address is on `.example`, `.invalid` or `gridlink.me`. A reply that escapes by
accident cannot reach a real person.

## Files

| | |
|---|---|
| `seed.py` | CLI and orchestration. Start here. |
| `content.py` | The mail corpus: threads, one-offs, newsletters, notices, junk, drafts. |
| `people.py` | The cast, shared by the mail corpus and the address book. |
| `events.py` | The 30 calendar entries, positioned relative to the run date. |
| `mailer.py` | MIME assembly and the IMAP session. |
| `dav.py` | A small CalDAV/CardDAV client, plus vCard and iCalendar serialisers. |
| `assets.py` | PNG, PDF and CSV generation, and the 5x7 font for monogram avatars. |

No third-party packages. Standard library only, so it runs on a machine where nothing has
been installed.

## Useful flags

```
--now 2026-08-18T09:00:00+00:00   fix the reference instant; with --seed this is byte-stable
--mail 40 --contacts 5 --events 5 a fast small mailbox
--dry-run                         build everything, write nothing, print the tally
--skip-mail / --skip-contacts / --skip-events
--wipe                            delete existing content first. Destructive, so type it.
--verify-tls                      on by default this is off, because the LAN host serves
                                  a certificate for a name the IP does not match
```

Re-running without `--wipe` adds a second copy of everything. That is deliberate.

## Two things the server does that are worth knowing

- **`--dav-base` must be a hostname, not an IP.** Caddy sits in front of Stalwart and
  selects on SNI, so `https://192.168.50.48/...` fails where `https://next.gridlink.me/...`
  works, even though they are the same machine.
- **Stalwart escapes the comma in a `PHOTO:` data URI** when it re-serialises a vCard, so
  what comes back is `base64\,iVBOR...`. The payload is intact and byte-identical; a
  client just has to unescape it. Worth remembering the next time a contact photo does not
  render.

## Gotcha that cost an hour

vCard 4.0 dates are ISO 8601 **basic** format. `BDAY:1958-09-21` is not valid, and
Stalwart does not reject it: it parses the leading `1958-09` and silently stores a
birthday with no day in it. Write `19580921`.
